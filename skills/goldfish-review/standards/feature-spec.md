# Feature-Spec Standard

A feature specification passes when an engineer new to the codebase can understand what is proposed, why, and what could go wrong.

It states, where they apply:

1. **Problem.** The user or technical problem, with evidence.
2. **Goals and non-goals.** What the feature delivers, measurably, and what it deliberately leaves out.
3. **Architecture.** Components, data flow and how it fits the existing system.
4. **Alternatives.** Other viable designs, each rejected for a stated technical or scope reason. A specification that presents a single path without alternatives fails.
5. **Risks and limits.** Failure modes, security implications, scaling limits and operational costs, each with its mitigation or an explicit acceptance.
